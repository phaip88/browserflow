# Architecture overview
- **Processes**: `api/web` (Next.js), `scheduler`, `browser-worker`, `postgres`. Each is an independent OS process; the optional embedded supervisor only spawns the latter two as child processes for single-command local runs.
- **Source of truth**: PostgreSQL. Executions are leased with `SELECT … FOR UPDATE SKIP LOCKED`; leases expire by DB clock; heartbeats extend them; the scheduler/worker reaper converts expired leases into `WORKER_LOST` and re-queues (new attempt) or fails.
- **Guarded writes**: every worker write verifies `(execution_id, attempt_id, worker_id, lease_token)` + current attempt + non-terminal status inside the same transaction.
- **Events**: `execution_events.sequence` is allocated by incrementing `executions.event_sequence` under row lock in the same transaction as the state change and the `outbox_events` row. The scheduler publishes the outbox via `pg_notify`; SSE clients replay from `lastSequence` and de-duplicate by event id.
- **Engine semantics**: single node at a time; DFS over edges ordered by kind, priority, id; `if` selects one branch (other branch targets SKIPPED); `foreach` executes the LOOP_BODY subgraph per item in an isolated LoopScope (item/index/length/first/last) then LOOP_DONE; FINALLY (from start) runs at most once; `return` stops the flow; unvisited nodes become NOT_REACHED. Cycles are rejected by the compiler.
- **Compiler** (`src/flow/compiler.ts`): schema → ids → node types/versions/config → bindings/types → handles → entry → cycles → reachability → loop subgraphs → plan + estimate + checksums. Never touches a browser.
- **Browser**: `BrowserSession` owns Chromium (ephemeral or persistent identity profile), installs the network policy on `context.route`/`routeWebSocket`, enforces page limits, captures bounded screenshots, and cleans up processes and runtime directories.
